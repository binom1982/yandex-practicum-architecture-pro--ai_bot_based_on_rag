# **Отчёт по Заданию 1: Исследование моделей и инфраструктуры**

## **Анализ задачи и стейкхолдеры**

* **Заказчик:** Руководство QuantumForge Software.
* **Цели бизнеса:**
  * Сократить затраты на поиск информации и коммуникацию.
  * Повысить продуктивность сотрудников (ускорить онбординг, принятие решений).
  * Автоматизировать ответы на повторяющиеся запросы.
  * Выявлять пробелы в документации.
  * Создать масштабируемое решение.
* **Пользователи:** разработчики, саппорт, менеджеры/аналитики, новые сотрудники.
* **Ограничение из ТЗ:** *«возможно, часть материалов не стоит уносить в облако, так как они являются конфиденциальными»* **.**

---

**1. Сравнение LLM-моделей**

| **Критерий**      | **Локальные (Hugging Face)**                         | **Облачные (OpenAI / YandexGPT)**                                |
| ------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Качество ответов | Зависит от модели, требует настройки | Высокое «из коробки»                                         |
| Скорость                | Зависит от локального железа               | Стабильная, оптимизированная                         |
| Стоимость              | Фиксированная (инфраструктура)           | Оплата за токен, растёт с масштабированием |
| Развёртывание      | Сложнее: среда, веса, квантизация        | Простое: API-ключ + минимум кода                         |

**2. Сравнение моделей эмбеддингов**

| **Критерий**            | **Локальные (Sentence-Transformers)**                | **Облачные (OpenAI Embeddings)** |
| ------------------------------------- | ------------------------------------------------------------------- | ---------------------------------------------- |
| Скорость индексации | Высокая на CPU, без лимитов                      | Быстрая, но есть лимиты API |
| Качество поиска         | Достаточное для технических текстов | Высокое, лучше семантика  |
| Стоимость                    | Бесплатно                                                  | Плата за 1K токенов              |

**3. Сравнение векторных БД**

| **Критерий**                         | **FAISS**                                                           | **ChromaDB**                                                                |
| -------------------------------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Скорость поиска/индексации | Очень высокая (C++ бэкенд)                              | Средняя, удобна для прототипов                          |
| Сложность внедрения              | Требует ручного управления метаданными | «Из коробки»: встроенный REST, авто-управление |
| Удобство                                   | Идеально для скриптов/бэкенда                   | Удобно для итераций, тяжелее в production                |
| Стоимость владения                | Бесплатно, минимальный оверхед                 | Бесплатно, но больше ресурсов                            |

**4. Рекомендуемая конфигурация сервера**

* **CPU:** 8+ ядер (обработка чанков, запуск квантованной LLM)
* **RAM:** 32–64 ГБ (индекс в памяти, кэширование)
* **GPU:** Опционально (1× RTX 4060 / T4). При использовании GGUF-моделей достаточно мощного CPU.

## **Варианты архитектуры и выбор**

| **Вариант**      | **Состав**                                                                                          | **Плюсы**                                                                                                                                     | **Минусы**                                                                                                                 |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Локальный         | Local LLM + Local Embeddings + FAISS                                                                            | Безопасность, фиксированные затраты, простота                                                                    | Требует ручной настройки, выше латентность, масштабирование ограничено   |
| 2. Гибридный         | Cloud LLM + Local Embeddings + FAISS                                                                            | Быстро, качественные ответы                                                                                                      | Промпты уходят в облако (риск для конфиденциальности)                                     |
| 3. Облачный           | Cloud LLM + Cloud Embeddings + Cloud Vector DB                                                                  | Низкий порог входа, минимум инфраструктуры                                                                          | Высокий OpEx (операционные расходы), риски передачи данных вовне                     |
| 4. Корпоративный | Выделенный GPU-сервер<br />+ Fine-tuned LLM <br />+ Domain-specific Embeddings <br />+ ChromaDB | Полный контроль, кастомизация под домен,<br />лучше качество на специфичных запросах | Высокий CapEx (капитальные расходы), нужна команда MLOps, <br />сложная поддержка |

**Выбор Архитектуры:** Вариант 1 (Локальный).
**Аргументация:**

* Соответствует ограничению ТЗ: *«часть материалов не стоит уносить в облако»* .
* Предсказуемый бюджет (нет платы за токен при росте ~400 страниц/мес).
* Достаточная производительность для текущих объёмов (~21k документов).
* Проще поддержка: нет внешних зависимостей.

**Выбор векторной БД:** используется  **FAISS**
**Аргументация:**

* Позволяет хранить индекс локально, что соответствует требованию о конфиденциальных материалах.
* Высокая скорость поиска на CPU при текущих объёмах данных.
* Нулевая стоимость владения и минимальная сложность интеграции (встроен в LangChain).
* Не требует развёртывания отдельного сервиса — упрощает контейнеризацию и эксплуатацию.
